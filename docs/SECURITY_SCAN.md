Generated by `python3 tools/security_scan.py` (Bandit, the Python security linter of PyCQA) over every Python file that runs (`omni_controller/`, `omnicompass/`, `realms/`, `tools/`, `scripts/`, `fleet/`, `k8s_controlplane/`; 54,023 lines). The workflow `security-scan.yml` runs it on every push to main that touches code, and every week, with `pip-audit` over every pinned dependency; it fails on a finding of high or medium severity that no review below names.

**1 finding of high severity and 40 of medium severity, every one reviewed below; 418 of low severity, counted by kind.** Fixed on 19 October: a world-writable PgBouncer folder (now owned by postgres, 0o755) and the MD5 that PostgreSQL's own password method defines, now marked as not used for security. Fixed in omni-v14 (21 October): the operator's own commands (the site power reading, a muscle's read command, a wall meter's) run without a shell unless they hold a pipe, a redirect or a variable, so the governor's site power reading no longer reaches a shell at all and one high finding is gone. Fixed on 3 November: the wall meter's command (`tools/wall_meter.py`, `cmd:`) runs without a shell at all, a pipe included (each stage's output into the next), and anything else only a shell reads is refused with the reason, so a second high finding is gone.
