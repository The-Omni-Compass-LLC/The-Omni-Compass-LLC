## The order and what was done

On 10 October 2026 the founder ordered that every benchmark be run again, right then, on the current code, native and omni,
with the wiring of each read against its rules before it ran: the Kubernetes tests, the five live stacks (Redis, Kafka,
PostgreSQL, MySQL, MongoDB), the simulators, the muscle tower and the four realms alone and stacked, the organisms with the
cluster inside and the big organisms on rented machines; the runs that take a day or two started again like the rest.

**Done between 01:24 and 01:31 UTC:** 70 GitHub runs and two Azure machines, every one from `main` at commit `3aac0ab7`
(GitHub records the commit on every run; all 70 read `3aac0ab7`), which `tools/omni_version.py --commit 3aac0ab7` reads as
**omni-v3**, digest `b53d05449ee04c4b`, 40 files: the frozen engine, unchanged. The working branch carries the identical tree.
Every benchmark has its two arms, **native** (the system on its own controller) and **omni** (Omni-Compass on top of that
controller; the arm is spelled `compass` in the workflows' inputs and in the raw files). The dispatch inputs are the
preregistered ones, read from each page before the dispatch and listed below run by run; nothing was typed in that the
rules do not say. Every run that lands is read by the three-run rule (`tools/confirm_abc.py` and the stacks' and
simulators' own table tools), every row kept, losses included.

**What stands meanwhile.** Every published table stands as the result until its new set lands. The new set is then the
result; the table it supersedes goes whole to `docs/history` with a line in `docs/history/README.md`; the Omni index
(`results/OMNI_INDEX.md`), the wiring page (`docs/WIRING_VERDICTS.md`), the benefit sheet (`docs/BENEFIT_SHEET.md`), the
dossier and the manual are read again from the new tables. A run is archived (`.github/archive_request.txt`, the archive
workflow copying its raw files to `results/live/raw/`) before its table is written, so every number can be checked.

## When a set lands

1. Its run ids go into `.github/archive_request.txt`; the archive workflow copies the raw files into `results/live/raw/run-<id>/`
   and checks them with SHA-256 sums.
2. The table tool reads the three archived runs and writes the table named above; the table it supersedes is moved whole to
   `docs/history` and listed in `docs/history/README.md`.
3. `tools/omni_index.py`, `tools/wiring_verdicts.py`, `tools/benefit_sheet.py` and `tools/dossier.py` are run again; the state of
   play, the register, how to read the results and the manual are brought to the new numbers; `tools/release_manifest.py` must
   read 0 FAIL before the push, and GitHub's verify run after it.
4. A set whose rows go against Omni is reported like any other. If a loss is ours (wiring, native set-up or scoring), that is
   fixed, declared as an amendment, and the set run again; the loss stays on record.
