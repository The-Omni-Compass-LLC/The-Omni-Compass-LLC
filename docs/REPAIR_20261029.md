The six-kube matrix could stop before measuring anything because its explicit sparse checkout omitted
the root engine declarations. The checkout now includes `OMNI_V*.json` and the orchestrator sources.
A regression test executes those checkout patterns against a real Git index and identifies the frozen engine.

The benchmark harness now lists pods before its workload window, then watches from that list's resourceVersion.
Every bounded watch continues from its last event or bookmark. An expired history, client failure, malformed
event or missing final Ready/scheduling transition rejects the arm. A final snapshot is used only to check
coverage; it never supplies substitute waiting measurements. A post-window Ready event is censored at the
window boundary. New-format evidence is checked again when the report reads it.

After the measured governor stops, benchmark cleanup atomically restores only a rollout annotated as paused
by Omni. It works whether that deployment is still paused or has already been resumed. The patch uses its
resourceVersion to reject concurrent changes and rereads the state before declaring restoration. This is a
benchmark cleanup repair; the released controller's standalone reset implementation has not been changed.

Exhausted final API reads now fail. Failed arms retain their original diagnostics, an INVALID marker and
checksums written at exit. The paired wrappers preserve that marker so they do not invalidate its checksum.
The evidence-audit and paired-protocol pages receive the repository's full required notices. The release
manifest is regenerated by its verification tool, without bypassing checks or changing scoring rules.

The verifier's compiler-only fallback now builds its required core-runs and immune executables as well,
matching the existing CMake targets. Their omission caused a local verifier failure on a machine without
CMake; this was independent of the Azure measurement failures. The paired evaluator and its tests also
receive their complete required source headers.

The watchdog and fault injector now resolve process IDs within their own PID namespace when procfs
is mounted from the host namespace. A host process ID must never be used as a container signal target.
Namespace identity and the kernel's NSpid mapping identify the process; the existing process-start-time
and registry ownership checks remain. This addresses the earlier local fault-injection and watchdog
test failures without skipping either test or relaxing its assertions.
The ownership test uses the real alternate UID where the kernel permits it. Where a user namespace
maps only one UID, descriptor metadata is modelled for that one case; both ownership-refusal and
explicit-trust assertions still run. That metadata case is not evidence of a real ownership transfer.

Validation covers sparse checkout, watch continuation, missing transitions, truncated/error events,
window censoring, failed collection, owned/foreign rollout cleanup, propagated write failures and
failed-arm checksum verification. The release's own verification receipt records the broader check.

The engine remains omni-v21 with its existing 63-file fingerprint. Its equations, controller rules,
presets and thresholds are unchanged. These repairs do not retroactively validate Azure repetitions
90 or 91, establish complete fleet restoration, or establish a performance gain. A fresh paired cloud run
on this source is required. The current v21 service-wait observations and the older Azure evidence remain
preserved. Live no-harm enforcement and whole-system useful-work admission still require separate
same-version integration evidence; this repair does not claim to complete them.
