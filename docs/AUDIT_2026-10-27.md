| # | Finding | Fix | Held by |

| 3 | The record behind the answer at the top of the README (`results/orchestrator/V18_THREE_ARMS_ABC.json`) had no tool: it was written by hand | `tools/three_arms_abc.py` builds it from the runs' own summaries by the one key; it rebuilds the published record byte for byte; the recipe is in `results/live/RECIPES.json` | `tools/reproduce.py`, `tests/test_audit_2026_10_27.py` |
| 4 | The answer at the top of the README showed Omni-Compass by itself, after the founder's order of 25 October that Omni-Compass is never by itself, and led with omni-v18's record while omni-v21 had its own tables | the answer leads with the engine that stands: the Omni index and the count of its benchmarks by word, read from the benefit sheet; the real-loop record shows two sides, native and Omni-Compass on native, its engine named; its omni-v21 runs were started the same day | `tools/headline.py`, `tests/test_audit_2026_10_27.py` |
| 5 | Pages still named an older engine as the one that stands: the README (omni-v19 as the engine and the factory profile, and a section narrating omni-v16 and omni-v11 results as current), the Owner's Manual (its evidence section on omni-v10 and omni-v11, its version history ending at omni-v11, the factory profile on omni-v19), `docs/FACTORY_PROFILE.md` (omni-v19), the state of play (its opening chronology from 10 October and an open list on omni-v11 and omni-v16), the live engine page (omni-v19, and a sentence that the by-itself code was removed, which it was not) and its appraisal (omni-v17) | each brought to omni-v21; the Owner's Manual's evidence table is written from the benefit sheet on every push; the state of play's chronology moved whole to `docs/history/STATE_OF_PLAY_2026-10-27.md` | `tools/land_engine.py --check` (run by `verify.py`) now holds every one of these sentences, so no engine can land while one of them names the last |
| 6 | The one finished card run (omni-v18, A100) reads EVEN with no write: the card's power limit was already at its top on native, so the factory tune had nothing to raise; no card run had set an operator's cap under it on its own | a `cap` mode on the GPU workflow: an operator's power cap underneath (70% of the default limit, set the same way in both arms), the cap alone against the cap with Omni-Compass on top, at the usual load and fully loaded; and a `dial` choice, so the card governor's tune-down (`--dial save`, the clock ceiling stepped below the top where the card's time on a request allows), which no workflow had ever passed to the card, can run; each mode and dial in its own lane, where a run of another mode with the same tag had waited behind a whole stacks run | `.github/workflows/lambda-gpu.yml` |
| 7 | A card receipt did not carry its own engine, so the page typed it into a sentence | every card run now writes the version tool's own answer on the card (`results/gpu/engine-<time>.txt`) and packs it with its results | `scripts/gpu_rented_run.sh` |
| 8 | The Google and Amazon sets cannot start | GitHub's own check of 27 October (`cloud-check`) reads all four keys absent from this repository's secrets (`GCP_CREDENTIALS`, `GCP_PROJECT`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`); the wiring stands and starts behind the check once they are stored | `docs/RUN_LEDGER.md`, `docs/GOOGLE_SETUP.md`, `docs/AMAZON_SETUP.md` |
