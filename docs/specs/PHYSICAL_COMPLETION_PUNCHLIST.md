## Status rule
The repository is hardware-ready. It is not a physical performance proof until an independent plant produces a sealed Native/Watch/Omni result under the current canonical controlled-evolve path.

## Frozen product
Do not alter the eight-line core, canonical C++ twin, frozen Python/C++ parity population, or XPASS8 canonical controlled-evolve mechanism to chase a benchmark result. XPASS6 energy-only candidates are historical tuning evidence, not replacement laws.

## Missing evidence
1. No qualifying `results/gpu/github-<run>/` physical NVIDIA result is shipped.
2. Historical Kind Set-22 evolved the plant with `u=0`; it is `pre-canonical-evolve`, not evidence for CLAIM1.
3. Watch zero-write, requested/enforced authority, physical GPU joules, CPU package joules, optional wall joules, service guardrails, and restoration must be printed by metal in the same sealed run.
4. The 128-muscle tower demonstrates simulated contracts, not 128 live APIs.
5. Fewer logical nodes/copies are not kWh savings unless hardware actually powers down or an independent energy meter records the reduction.
6. Allocator churn remains an adverse modeled result in several workload classes and must remain visible.

## Current mechanism identity
`OMNI_CLAIM_MODE=CLAIM1` is the default current mechanism. Assimilated state is evolved through the canonical bounded FF+P microsteps using the locked target sign. Allocation gates consume the held `u` from the accepted canonical microstep. They do not recompute a second post-evolve command.

`OMNI_CLAIM_MODE=LIVE_GATE` exists only to reproduce the historical Set-22 architecture for controlled A/B diagnosis: evolve with `u=0`, then calculate a post-evolve command used only as a gate. Results from this mode must be labeled compatibility evidence, never current-governor evidence.

## Physical GPU completion
Run preflight, then smoke, then the counted run. Keep failures. The counted run must preserve Native/Watch/Omni arms, frozen work unit, SLO, GPU identity, driver, requested/enforced limits, clock-event reasons, device energy, integrated draw cross-check, RAPL package energy, Omni CPU seconds, write counts, restoration and optional independent wall energy.

The run is invalid if Watch writes, restoration fails, required authority readback is unavailable, frozen code changes, a foreign compute process occupies the selected GPU, or the experiment violates its preregistered conditions. Thermal or hardware-power-brake evidence must not be credited as an Omni efficiency mechanism.

## Kind completion
Create a new live repetition series with a new paired script (as `scripts/kind_paired.sh`). Never overwrite or silently upgrade Set-22. Report p95/p99, pending work, replica/node behavior, Omni CPU overhead, Watch zero writes, restoration and an honest energy label. Kind's modeled power is not a physical energy meter.

## Allocator holdout
Tune only declared allocator parameters such as `down_dwell`, `down_band`, `push_release`, `U_gate`, and `cap_min`. Development sweeps may identify candidates, but no small-seed winner becomes a universal law. Preserve work, health, backlog, power/thermal violations, reversals and unsafe-action gates. Held-out evaluation stays held out.

## Definition of done
A physical completion claim requires a sealed physical GPU result plus a current-CLAIM1 Kind re-pair. The result is published whether favorable, adverse or inconclusive. No stand-in `github-*` directory is ever generated by the repository.
